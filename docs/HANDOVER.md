# Handover guide: for the next developer

Read in this order: `docs/APPLICATION_MAP.md` (what exists and must be protected), `docs/KNOWLEDGE_CENTRE_PRE_IMPLEMENTATION_PACKAGE.md` (architecture and decisions), `docs/PUBLIC_SITE_PHASE2.md` (the public website), `docs/SERVICE_WORKER_CHANGE.md`, `docs/BACKUPS.md`.

## The system in brief
One Node/Express server (TypeScript) with a React app, PostgreSQL through Prisma, files in Cloudflare R2, email through Resend. One Render web service, Frankfurt. The same server writes the public website (`/en`, `/fr`) and serves the member app.

## Run it
| Task | Command |
|---|---|
| Install | `npm install` (from the repository root) |
| Server tests | `npm run test --workspace server` (needs a local PostgreSQL; `server/.env.test` names the test database; about 35 minutes for the full run) |
| Screen tests | `npm run test:client` |
| Build | `npm run build` |
| Database changes | `npm run prisma:migrate --workspace server` while developing; they are applied automatically on deploy |

## Deploy
Pushing to the branch `claude/god-nation-referral-mvp-sjpz82` deploys automatically on Render (build, database changes, seed, start). `main` is kept identical.

## Switches and secrets (names only)
`PUBLIC_SITE_ENABLED` (public website), `DATABASE_URL`, `DIRECT_URL`, `RESEND_API_KEY`, `EMAIL_FROM`, `VAPID_*`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `META_CAPI_TOKEN`, `TIKTOK_EVENTS_TOKEN`, `UNSUBSCRIBE_SECRET`, `APP_URL`, `CLIENT_URL`. Values live in Render and GitHub secrets only.

## Rules that must not be broken
1. Never change existing addresses, sign-in, cookies or the installed app's identity. Tests guard this (`existingAddressesContract`, `existingApiContract`, `serviceWorkerPublicArea`).
2. Public pages are written before the cookie steps and set no cookies.
3. Public content and private content stay in separate tables and separate storage.
4. Nothing generated by AI is published without a person's approval.
5. A French page is public only after the French reviewer approves it.
